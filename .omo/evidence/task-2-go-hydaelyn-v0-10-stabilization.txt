- Lifecycle RED: a blocking Transport.Connect caused Close to exceed the 250ms bound because Initialize held Client.mu across SDK Connect; the transport never observed context cancellation.

A live 50ms header timeout rejects a server that withholds headers, while flushed SSE headers allow a 100ms idle body and subsequent event delivery.

GREEN: all configured custom headers inject only when scheme, canonical hostname, and effective port match the endpoint. TERMINAL STATE AND 4 MIB INBOUND BOUND FOLLOW-UP
- Initialize is now terminal and single-use across success, failure, and cancellation. RED counting transports observed 2 sequential and 3 concurrent Connect calls; GREEN observes exactly 1 and reuses the cached result/error. A waiting caller may cancel its own wait without starting another Connect.
- Close now has one owner and one closeDone publication point. RED concurrent callers returned nil before cleanup or returned before a blocked resource close; GREEN all callers wait for initialization cancellation and resource cleanup, then return the same joined error. Close wins over concurrent Initialize and later public operations.
- RED real 307/308 cross-origin redirects leaked Mcp-Session-Id. GREEN strips configured credentials plus Mcp-Session-Id, Mcp-Protocol-Version, and Last-Event-Id; same-origin redirects retain the headers and request cloning leaves the original unchanged.
- NewHTTPTransport no longer asserts that http.DefaultTransport is *http.Transport. A replacement RoundTripper no longer panics; fallback transport values mirror the standard library and retain the 30-second response-header-only timeout.
- InboundLimitError is the typed, sticky public boundary for messages over 4 MiB. NDJSON counts each physical line, SSE resets only at a blank event delimiter, and HTTP JSON counts the complete response body. Exactly 4 MiB passes; the next byte fails.
- Explicit StreamTransport wraps its reader before official IOTransport. HTTP wraps JSON/SSE response bodies before the official StreamableClientTransport parser. HTTP operations fail fast after overflow but DELETE remains available for session cleanup.
- Official CommandTransport exposes no reader hook, so DialStdio uses a minimal commandIOTransport for pipes/process lifecycle and delegates NDJSON decoding and MCP protocol ownership to official IOTransport. A real official stdio server returning a message over 4 MiB is rejected, and Close waits until the subprocess has exited.
- No handwritten JSON-RPC, JSON decoder, SSE field parser, reconnect/session state, or Content-Length framing was introduced.
