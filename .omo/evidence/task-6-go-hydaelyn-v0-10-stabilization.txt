Implemented checks
- Checkout keeps fetch-depth: 0, then explicitly fetches origin/main.
- The peeled GITHUB_SHA commit must be an ancestor of origin/main before the
  release gate can pass.
- staticcheck is pinned to v0.7.0 and govulncheck to v1.3.0; no @latest
  analysis tool remains in the release workflow.
- Sentrux is pinned and installed exactly like CI at v0.5.7, including the Go
  grammar plugin, and make architecture-check is part of release-gate.
- The tagged CLI is installed into a temporary GOBIN with GOPROXY=direct. Its
  version must equal GITHUB_REF_NAME; --help must succeed; an unknown command
  must exit 1 with empty stdout and non-empty stderr.
- A temporary consumer writes its skill import first, pins the same tag, then
  runs go mod tidy before go test ./... and go build ./.... This ensures lazy
  module loading records skill's gopkg.in/yaml.v3 dependency in go.sum.
- The GitHub Release job still has needs: release-gate, so no release creation
  can bypass these checks.

Not locally verifiable
- A new tag cannot be pushed or a GitHub Release created under this task's
  explicit no-publish constraint. The workflow's actual GitHub tag event and
  release API call therefore remain CI-only checks.

Residual risk
- GOPROXY=direct depends on GitHub availability and a pushed tag being visible
  from the runner. That dependency is intentional: the gate validates the same
  public source path consumers use instead of the checked-out working tree.
