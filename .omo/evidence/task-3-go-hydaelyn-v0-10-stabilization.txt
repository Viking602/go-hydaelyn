Task 3 evidence: official Streamable HTTP transport
Date: 2026-07-10

RED TO GREEN
- RED: a custom header set containing text/plain Content-Type/Accept and spoofed MCP session/protocol values overrode SDK headers; the official strict handler rejected initialize with `Unsupported Media Type`.
- GREEN: headerRoundTripper now ignores only SDK-owned Content-Type, Accept, Last-Event-Id, Mcp-Protocol-Version, and Mcp-Session-Id values while preserving other cloned custom headers.
- The wrapper still delegates Connect directly to mcp.StreamableClientTransport and contains no SSE parser, session state, retry loop, or notification implementation.

REAL OFFICIAL SERVER
- Ran the same Initialize -> ListTools -> CallTool -> Close scenario against official NewStreamableHTTPHandler in JSONResponse=true and JSONResponse=false modes.
- Initialize mapped server name and negotiated protocol to the existing Hydaelyn InitializeResult.
- ListTools mapped name and inferred object schema to message.ToolDefinition.
- CallTool mapped text and structured content to the existing Hydaelyn CallToolResult.
- Observed application/json and text/event-stream call responses respectively.
- Observed every POST using Accept `application/json, text/event-stream` and Content-Type `application/json`.
- Observed notifications/initialized return HTTP 202 with the negotiated session and protocol headers.
- Observed post-initialize calls carry Mcp-Session-Id and Mcp-Protocol-Version.
- Observed Close issue HTTP DELETE with the same session and protocol headers.

BOUNDARY AND ERROR CONTRACTS
- Custom header input is cloned at construction; later caller mutation does not affect requests.
- RoundTrip clones each request/header before adding custom values, leaving the shared request unchanged.
- HTTP client default timeout is exactly 30 seconds.
- Unsupported protocol and HTTP 400 both fail Initialize and leave the client session uninitialized. The SDK unsupported-version error type is unexported, so tests intentionally avoid string parsing.
- HTTP 404 after initialization returns an error matching mcp.ErrSessionMissing.
- HTTP JSON-RPC tool failure maps to the existing RPCError with Code/Data and still unwraps to the SDK jsonrpc.Error.
- Canceling a CallTool context returns an error matching context.Canceled and the official server handler observes cancellation and exits.

FINAL REVIEW: STREAMING TIMEOUT AND REDIRECT SECURITY
- Replaced the 30-second http.Client total timeout with a 30-second ResponseHeaderTimeout on a cloned http.DefaultTransport, so handshake/header stalls remain bounded without imposing a lifetime on SSE response bodies.
- Live timing tests prove missing headers time out at a shortened bound and immediately flushed SSE headers survive an idle period twice that bound before delivering an event.
- Custom headers are now endpoint-origin scoped using scheme, canonical hostname, and effective port. Cross-origin redirect and HTTPS downgrade receive none; same-origin redirect preserves configured non-SDK headers.
- No SSE parser, session state, reconnect loop, framing, or message-size layer was introduced. The official SDK remains the protocol owner.
- Official JSON/SSE lifecycle tests, MCP race count20, full repository tests/vet, targeted lint, consecutive Sentrux, and architecture-check all passed.

FINAL REVIEW: REDIRECTED SDK HEADERS AND BOUNDED RESPONSES
- RED real 307 and 308 cross-origin redirects forwarded SDK-owned Mcp-Session-Id after initialization. GREEN removes session, protocol, and last-event IDs together with Authorization, Cookie, and Proxy-Authorization whenever the redirect target origin differs.
- A real same-origin 308 keeps origin-bound headers, and reflect-based request snapshots prove RoundTrip never mutates the original request headers.
- HTTP JSON response bodies and individual SSE events are bounded at 4 MiB before official SDK parsing. Oversize JSON becomes a sticky InboundLimitError and subsequent non-DELETE calls fail without network I/O; Close still emits DELETE. Oversize SSE fails without an unbounded reconnect cycle.
- Multiple individually valid SSE events may exceed 4 MiB in aggregate because the guard resets only on the blank SSE event delimiter.
- The wrapper still delegates JSON-RPC, event field parsing, session handling, reconnect behavior, and protocol negotiation to official StreamableClientTransport.
- A non-*http.Transport replacement for http.DefaultTransport no longer panics during NewHTTPTransport; a standard-library-equivalent clone is used as a safe fallback.
- `go test -race ./transport/mcp/client -count=20` passed in 169.266s; `make verify`, `make ci-local`, normal architecture-check, and a temporary-index architecture-check including all untracked files all passed.
