# Hydaelyn v0.8.0 — Public Framework Release

**Theme**: General-purpose, durable, governed Agent runtime for Go.

v0.8.0 lifts Hydaelyn from "runnable runtime" to "publishable framework". Every cross-cutting concern an Agent application meets in production gets a stable, documented public surface — and nothing else creeps into the kernel.

> **Status:** as-built notes for the v0.8.0 implementation drop. Items listed under "Headline changes" landed in this release; items moved to "Scope deferred to v0.8.1+" were named in the design plan but did not ship. The line counts and CI matrices are canonical against the tagged commit.

---

## Headline changes

### 1. Capability layer (`api.Capability` + `CapabilityManifest`)

A declarative schema for anything an Agent can invoke. One source of truth, with bidirectional projection to model-call tools:

- `api.Capability` — agent/program-boundary descriptor (schemas, effect type, risk, idempotence, tags).
- `api.CapabilityManifest` — bundle of Capabilities a system publishes.
- `Tool.AsCapability(agentID)` and `Capability.AsTool()` — lossless-where-shape-overlaps adapters; existing Tools become Capabilities without code changes.
- `api.CapabilityStore` — registry-style storage interface with `CapabilitySelector` filtering.
- `transport/mcp/` — MCP descriptor export (ships in v0.8.0).

Reserved namespace `hydaelyn.self.*` (four read-only names) is claimed in v0.8.0 and implemented in v0.9.0. See ADR-009.

> Deferred to v0.8.1+: OpenAPI 3.1 operation renderer (`transport/openapi/`) and CLI subcommand generator (`cmd/capabilitycli/`). The CapabilityManifest shape is already the seed format both renderers will consume — no breaking shape changes are anticipated.

### 2. AgentDefinition + selector-based discovery

`api.AgentDefinition` (new) is the declarative, version-controlled spec an operator publishes ahead of time. It carries Instructions, ModelPolicy, Capabilities (by name), Context sources, Triggers, Governance, Status, and PreviousVersionID. `AgentDefinition.AsProfile()` derives the runtime `AgentProfile` used for write attribution.

Discovery primitives:

- `api.AgentProfileStore` with `ListAgentProfiles(ctx, AgentSelector)`.
- `api.CapabilityStore` with `ListCapabilities(ctx, CapabilitySelector)`.
- `api.RunSelector{ AgentID, AgentVersion, Statuses, Since, Until, Limit }` + `RunStore.ListRuns`.
- `Run.AgentVersion` stamp on each Run.

See ADR-014 for the agent-ontology stance these changes formalize.

> Implementation note: design proposed extending `AgentProfile` itself with `Status` / `PreviousVersionID` / `ModelPolicy`. The shipped shape places those on the new `AgentDefinition` type instead, leaving `AgentProfile` as the slim runtime-identity record (ID + Role + Groups + Metadata) it has always been. This keeps the "write attribution" hot path additive.

### 3. Worker Runtime + Trigger Runtime

`worker/runtime.go` — `EnvelopePoller` + `EnvelopeExecutor` plug-points, configurable concurrency, heartbeat, graceful drain, dead-letter routing. Hosts ship their own poller (NATS / Redis / Kafka / in-process); a `ChannelPoller` is bundled for tests and in-process use.

`transport/scheduler/` — robfig/cron v3 scheduler driver (second-precision, configurable timezone).
`transport/webhook/` — `http.Handler` factory keyed by (method, path), 1 MiB default body cap, optional token verifier.
`transport/event/` — in-process pub/sub keyed by topic, with attribute-AND filtering.
`transport/trigger/` — shared trigger context + Handler/HandlerFunc types every driver consumes.

Trigger kinds: `api.TriggerManual`, `api.TriggerSchedule`, `api.TriggerWebhook`, `api.TriggerEvent`.

### 4. Storage contract (Position D) — ADR-012 revised

> The framework owns the contract and the contract test suite. The framework ships no `api.StoreProvider` implementation.

v0.8.0 ships the `api.StoreProvider` contract + the 35-case contract test suite in `contract/` and nothing else. The earlier-planned Layer 2 (`storage/{memory,sqlite,mysql,postgres,sqlbase}`) was deleted before release per the 2026-05-24 revision to ADR-012 (Position D). Applications implement the contract against their own data stack (ent / gorm / sqlc / DBA-controlled DDL) and validate with `contract.RunStoreProviderContractTests`.

This is a continuation of the same purification stance that made `api.Memory` an optional plugin (see `13-memory-optional-plugin.md`): the framework owns the verbs and invariants, the application owns the nouns, the schema, and the storage.

The framework's own CI exercises the contract suite via a non-exported in-memory adapter at `contract/internal/inmemfake/` — same correctness bar, structurally unreachable from user code. An ent-based template for the application-side implementation lives in `docs/product-spec/v0.8.0/12-migration-guide.md`.

`contract.RunStoreProviderContractTests` is exported for ecosystem adapter authors. Same gate the framework runs in its own CI.

### 5. Usage metering + declarative governance — ADR-010

- `api.UsageRecord` + `api.UsageSelector` + `api.UsageStore` — append-only cost accounting (provider / model / tool / duration / credits), reachable through `StoreProvider.UsageRecords()`.
- `api.Budget` + `api.Quota` — declarative limits attached to an AgentDefinition's `GovernancePolicy`. The shape lets a deployment cap tokens, tool calls, runtime, and credits per run, and runs-per-window across runs.
- `api.GovernancePolicy.ApprovalRequiredFor` — names ToolEffectType values that always require human approval before execution, independent of the capability's own `RequiresApproval` flag.

> Deferred to v0.8.1+: the `BudgetPolicy` PolicyEngine adapter and the `PolicyEnforcer` with six built-in obligation kinds (the five call-site enforcers described in ADR-010 §"obligations"). The data shapes they will consume — UsageRecord and Budget — are stable in v0.8.0; the enforcement code path follows.

### 6. Context — Blackboard plus declarative ContextSource — ADR-011

| Layer | Scope | Lifetime | Status in v0.8.0 |
| ----- | ----- | -------- | ----------------- |
| Blackboard | Run | Run | `BlackboardReadWriter` (unchanged from v0.7) |
| ContextSource | Reference | N/A | `api.ContextSource` type + `ContextScope` constants on AgentDefinition |
| Memory | Agent/User/Tenant | Long-term | **Optional plugin** (`api.Memory[T Identified]` interface ships; no reference implementation, by design — see ADR-013 / `docs/product-spec/v0.8.0/13-memory-optional-plugin.md`) |
| Artifact | Run/Project | Long-term | **Deferred to v0.9.0** (`api.ArtifactStore` interface) |

`ContextSource` is declarative-only in v0.8.0 — it tells the registry what an Agent will pull from at run-start, but resolvers ship in packs (and in v0.9.0 for the framework default).

### 7. Evaluation framework

`eval/` — `Outcome` bundle, `Case`, `Suite`, `Assertion` interface, deterministic `Run`/`Eval` drivers, and a compact failure-report shape (`FailureRow`, `SummaryLine`).

`eval/assert/` — four built-in assertions: `Contains`, `Equals`, `Regex`, `JudgedBy`. The framework does not execute the run — callers drive their own Runner and pass an `Outcome` to `eval.Eval` or `eval.Run`. This keeps `eval/` provider-free and runnable in CI without a model key.

Semantic-similarity assertions deferred to v0.9.0.

### 8. Vertical pack registry — `packs/`

`packs.Pack` bundles AgentDefinitions, CapabilityManifests, Recipes, and EvalSuites into a single declarative value the host registers via `packs.Register(registry, pack)`. Four skeleton packs ship — `packs/research`, `packs/customersupport`, `packs/devops`, `packs/aiops` — each demonstrating the bundle shape without binding to a specific backend. Hosts wire concrete capability handlers when they mount a pack.

### 9. Architecture boundaries published

Five principles in `docs/product-spec/v0.8.0/09-boundaries.md`:

1. Core has no domain vocabulary
2. Recipes compile to Run/Task; no second runtime
3. Capability ≠ Procedure ≠ Policy ≠ Runtime
4. All side effects must be auditable
5. All long-running work must be resumable

ADR-009..014 each cite the principle they enforce.

The boundary itself is enforced in CI by two gates:

- `scripts/check-business-words.sh` — caps domain-vocabulary leakage at a baseline of 0 outside `_examples/`, `docs/`, and `pattern/`.
- `scripts/check-public-any.sh` — forbids `[]any` return types in `api/` and the root package.

## Breaking changes (mechanical)

All breaking changes are public-API changes with mechanical migrations.

1. `api.Flow` — removed `BypassTaskStore`, `BypassPolicyEngine`, `BypassTaskExecutionLease`, `BypassHandoff`, `BypassResponseLayer`, `BypassOutputGateway`. Recipes no longer carry bypass switches; the runtime owns the invariants.
2. `api.ErrFlowBypass` removed.
3. `Runner.ExecuteCommand(StartRunCommand)` returns `api.StartRunResult` (was `[]any{Run, RootTask}`).
4. `Runner.ExecuteCommand(RequestApprovalCommand)` returns `api.RequestApprovalResult` (was `[]any{Approval, Token}`).
5. `Runner.ExecuteCommand(AcquireTaskExecutionCommand)` returns `api.AcquireTaskExecutionResult` (was `[]any{Lease, bool}`).

`AgentProfile` itself is unchanged — new declarative fields live on the new `AgentDefinition` type.

### Package additions

- `worker/` — worker runtime (poller + executor + heartbeat + drain)
- `transport/scheduler`, `transport/webhook`, `transport/event`, `transport/trigger` — Trigger drivers
- `eval/` + `eval/assert/` — assertion framework
- `packs/` + `packs/{research,customersupport,devops,aiops}` — vertical pack registry + skeletons
- `contract/` — exported StoreProvider contract test suite (plus a non-exported `contract/internal/inmemfake/` adapter used solely by framework CI to self-test the suite)

See `docs/product-spec/v0.8.0/12-migration-guide.md` for the v0.7 → v0.8 upgrade path and a complete ent-based provider template.

## Scope deferred to v0.8.1+

The following items were named in the v0.8.0 design plan but were not implemented in this release. None of them require a breaking change to the v0.8.0 surface to land later.

### Capability ecosystem

- **OpenAPI 3.1 operation renderer** (`transport/openapi/`) — design ready; the `CapabilityManifest` shape is the seed.
- **CLI subcommand generator** (`cmd/capabilitycli/`) — design ready; same seed.
- **`hydaelyn.self.*` four built-in capabilities** — names reserved in v0.8.0; implementations in v0.9.0.

### Governance enforcement

- **`api.BudgetPolicy`** (PolicyEngine adapter for declarative Budget) — `Budget` and `UsageRecord` types ship in v0.8.0; the PolicyEngine adapter that joins them does not.
- **`api.PolicyEnforcer` + six built-in obligation kinds** — applied at five call sites (Blackboard read, Tool result, Trace export, Handoff, User message). Obligation routing lives in the policy decision today; the side-effect kit follows.

### Context

- **`api.MemoryEntry` and `memory/inmem` store** — retired. `api.Memory[T Identified]` ships in v0.8.0 as an optional plugin (ADR-013 revised); the framework no longer plans a reference implementation. `ContextSource` and `ContextScope` continue to ship as declarative anchors.
- **`api.Artifact` / `api.ArtifactStore`** — same status. `BlackboardItem.ArtifactRefs` lets a Run point at artifacts today; the store interface is deferred.
- **`recipe/memory-pyramid/` L0→L3 extraction pipeline** — deferred to v0.9.0.
- **`recipe/context-canvas/` Mermaid symbolic short-term memory** — same.
- **Knowledge-graph resolver** (`ContextSourceKnowledgeGraph` reserved Kind) — deferred to v0.9.0.

### Storage

- **Postgres `LISTEN/NOTIFY` Subscribe** — deferred. Postgres reference impl reports `SupportsBlackboardSubscribe = false` and the contract suite covers polling.

### Observability

- **`observe/otel/` OpenTelemetry exporter integrations** — deferred to v0.9.0+. The runtime already emits structured events and traces via `api.TraceStore`; the OTLP bridge is what's missing.

### Evaluation

- **Semantic-similarity eval assertions** — deferred to v0.9.0; v0.8.0 ships deterministic assertions only (`Contains`, `Equals`, `Regex`, `JudgedBy`).

### Packs

- **Substantive pack content** — `packs/{research,customersupport,devops,aiops}` ship as skeletons with shaped AgentDefinitions and CapabilityManifests in v0.8.0. The research pack also includes a smoke eval suite as a worked example. Production-grade pack content lives in v1.0.0+ or community contributions.

### Agent ontology

- **`AgentProfile.ContextSources` binding field** — deferred to v0.9.0 once resolver patterns are clearer.
- **AgentInstance** (multi-instance per Profile, proposed in ADR-001) — remains deferred.
