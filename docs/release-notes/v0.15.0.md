# Venat v0.15.0

Status: **Released**

Released on 2026-08-23.

v0.15.0 completes the public-API boundary program and expands Venat's agent
runtime for lossless multimodal provider traffic, governed concurrent tools,
live turn control, stable Skill activation, and durable host-scheduled
subagents.

## Public API boundary

- Public runners, stores, commands, leases, governance, and blackboard access
  converge on `api` types. Internal model and adapter mirrors are removed.
- `RunAdmin`, `Governance`, and `Blackboard` expose narrow host capabilities
  instead of embedding the complete runner.
- Context-taking APIs are the only public runtime entry points for operations
  that may block or touch persistence. Removed no-context compatibility helpers
  require callers to pass their own lifecycle context.
- Coding-pack runtime-name drift is checked at the public integration boundary,
  keeping the coding package independent from private runtime packages.

## Provider and message fidelity

- Messages preserve ordered text, commentary, final-answer, reasoning,
  redacted-reasoning, image, audio, file, source, and provider-data parts.
- Provider streams require exactly one terminal event at the end. A separate
  partial-stream normalizer handles interrupted live streams without accepting
  malformed completed responses.
- SSE frames and complete provider turns have independent aggregate line,
  event, byte, and tool-call ceilings. Tool-call IDs must be non-empty and keep
  one stable stream-index binding.
- Usage distinguishes reported cache reads and writes, including explicit zero,
  and carries reasoning tokens. Stop reasons distinguish model length and
  content-filter termination from the agent loop's max-turn ceiling.
- Prompt-cache keys, service tier, parallel-tool preference, native tool hosts,
  and context-usage observers are typed request channels. `ExtraBody` remains a
  bounded, JSON-only provider-wire extension and cannot smuggle host objects.

## Governed tool execution

- Tool input schemas compile at registration and validate every model call
  before approval or execution. Duplicate JSON keys, including escaped aliases,
  fail as recoverable tool results with no side effect.
- Duplicate or invalid tool registrations fail construction instead of silently
  replacing the first driver.
- Per-tool parallel, sequential, exclusive, shared-group, and bounded-concurrency
  policies replace tool-name-specific dispatch rules.
- Parallel batches use a fixed worker pool, cap total calls, and share frozen
  limiter state across cloned, subset, Skill, and governed tool buses.
- Live steer, follow-up, abort, and abort-with-prompt controls use reserve,
  checkpoint, acknowledge, and release phases. Mid-tool steering closes only
  slots proven not to have started; running unknown outcomes stay suspended for
  durable reconciliation.

## Skills and subagents

- Skill activation and resource tool schemas remain stable across turns.
  Activation authorization restores from durable activation results, so later
  runs do not mutate the provider's static Skill prefix merely to keep resource
  reads authorized.
- `Engine.SubagentScheduler` gives applications one durable scheduling boundary
  for agent-as-tool children. `SubagentRequest` carries a deterministic parent
  operation-slot identity, complete task and engine input, and restart-safe
  depth.
- Scheduler errors distinguish proven-not-started work from unknown outcomes.
  Child token reservations are shared across parallel calls, and usage already
  recorded against the parent durable budget is not persisted twice.
- Embedded applications retain the synchronous fallback. Both paths share
  budgets, usage accounting, failure mapping, recursion limits, and terminal
  result semantics.

## Upgrade

v0.15.0 contains intentional public API removals and interface changes. Migrate
callers to the canonical `api` types and context-taking helpers before upgrading.

```bash
go get github.com/Viking602/venat@v0.15.0
go install github.com/Viking602/venat/cmd/venat@v0.15.0
go mod tidy
```

Custom `StoreProvider`, provider, tool, and subagent scheduler implementations
should run their contract suites after the upgrade.
