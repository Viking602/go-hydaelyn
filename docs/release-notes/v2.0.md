# Hydaelyn v2.0 — Framework Purification Release

**Theme**: Hydaelyn v2.0 separates *framework* from *business*. The runtime
ships only mechanism (Run/Task state, Mailbox, Blackboard, Handoff,
Approval, Trace, Tool, Policy). All domain semantics — research, review,
incident, action — now live in user code, not the framework.

---

## Headline changes

### 1. Public API: legacy aliases removed
`hydaelyn.go` no longer re-exports archived host/team types. The
top-level package now surfaces the v2 runner API.

**Removed re-exports**: the old team runtime/config/request/profile aliases and
old orchestrator constructor aliases are no longer part of the primary surface.

**New canonical entrypoint:**
```go
runner := hydaelyn.New()
runner.RegisterAgent(hydaelyn.AgentProfile{ID: "alice", Role: "researcher"})
```

### 2. New primitives (M2)

**Mailbox fan-out** — one task can produce N envelopes:
```go
envs, _ := rt.DispatchTaskFanOut(ctx, orchestrator.FanOutDispatchTaskCommand{
    To: orchestrator.Address{Kind: orchestrator.AddressKindRole, Role: "specialist"},
})
```
`AddressKind` ∈ `{Agent, Role, Group}`.

**Blackboard subscribe + wait** — block on a predicate over the live stream:
```go
items, _ := rt.WaitForBlackboard(ctx, runID, filter,
    func(items []orchestrator.BlackboardItem) bool { return len(items) >= 3 },
    5*time.Second,
)
```
`rt.Subscribe()` exposes the underlying channel.

**DAG await semantics** — task dependencies now have explicit modes:
```go
orchestrator.CreateTaskCommand{
    DependsOn:          []string{"a", "b", "c"},
    AwaitMode:          orchestrator.AwaitModeQuorum,  // or All / Any
    AwaitQuorum:        2,
    OnDependencyFailed: orchestrator.OnDependencyFailedContinue, // or Skip / Fail
}
```

### 3. Framework business-word removal (M3)
The runtime no longer ships domain constants. Removed from
`internal/core/types.go` and `orchestrator/types.go`:
- `TaskTypeSynthesis`, `TaskTypeReview`, `TaskTypeAction`
- `BlackboardItemSynthesis`, `BlackboardItemReviewResult`, `BlackboardItemActionResult`

**Migration**: drive action gating off `Tool.RequiresActionTask` (declarative)
and `Task.AllowsAction` (per-task opt-in) instead of branching on a hardcoded
`TaskType`. Use `Task.Tags []string` for any business taxonomy you need.

### 4. CLI: library-first
The `hydaelyn` binary v1 (recipe / eval / pattern / deepsearch / team
subcommands) was removed. v2 ships a deliberately minimal CLI:
```
hydaelyn version
hydaelyn inspect-events --events PATH [--task TASKID]
hydaelyn help
```
Hydaelyn is now a *library*. The richer v1 CLI lives on the
`archive/legacy-v1` branch for reference.

### 5. `legacy/` deleted
The entire `legacy/` tree (host, team, mailbox, storage, eval, planner,
pattern/{deepsearch,collab,panel,research}, scheduler, recipe, capability,
observe, transport, tool/fixture) was removed from `main`. Full history is
preserved on `archive/legacy-v1`.

### 6. Promotions
- `legacy/tool/kit` → `tool/kit` (now a top-level package)
- `internal/slow` → deleted (no v2 use case)

## Architecture rules now enforced (CI)

`.sentrux/rules.toml` is checked on every PR:
- `max_cycles = 0` — no circular dependencies
- `max_coupling = "B"` — no file may exceed coupling grade B
- `no_god_files = true` — no file may depend on > ~15 modules

`docs/adr/ADR-008-framework-vs-business.md` is the durable rationale: when
in doubt, the framework provides mechanism; the user provides meaning.

## How to build the reference architecture

The full "user → orchestrator → blackboard → mailbox → N specialists →
aggregator → reviewer → actuator" workflow is in `_examples/incident_response/`
(~200 LOC). Each primitive shown is in a focused recipe:

| Primitive | Example |
|-----------|---------|
| Approval round-trip | `_examples/approval/` |
| Mailbox dispatch + ack | `_examples/mailbox_pingpong/` |
| Blackboard read/write | `_examples/dataflow/` |
| Replay (event-sourced) | `_examples/durable/` |
| Run-event metrics | `_examples/evaluation/` |
| Quorum dependency gate | `_examples/panel/` |
| Group fan-out | `_examples/research/` |
| Handoff | `_examples/collab/` |
| Tool registration + invoke | `_examples/tooling/` |

Workflow recipes ported from the archived pattern implementations:
- `_examples/recipes/research/` — parallel evidence + synthesis
- `_examples/recipes/deepsearch/` — research → verify → synthesize chain
- `_examples/recipes/collab/` — multi-branch handoff + quorum
- `_examples/recipes/panel/` — Role fan-out + claim collection

## Migration cheat sheet

| v1 | v2 |
|----|----|
| archived team constructor | `hydaelyn.New()` |
| archived team request with patterns/profiles | Compose primitives directly — no patterns/planners |
| archived profile model | `hydaelyn.AgentProfile{ID, Role, Groups}` |
| archived pattern registration | Compose tasks + DependsOn + AwaitMode in user code |
| archived team start | `runner.StartRun(ctx, cmd)` then explicit task dispatch |
| archived mailbox send | `runner.DispatchTask(...)` (typed envelopes) |
| `TaskTypeAction` constant | `Task.AllowsAction = true` + `Tool.RequiresActionTask` |
| `BlackboardItemSynthesis` | User-defined `BlackboardItemKind` value |

For exhaustive examples, see `_examples/recipes/` for direct ports of the
removed legacy patterns.

## Acknowledged scope deferrals

- **Sub-package split of `internal/core/`** — The original M5 plan
  proposed splitting `internal/core/` into 7 sub-packages to recover
  modularity. Data analysis after M3/M4 showed the core files (now
  551L for `types.go`, 592L for `runtime.go`) are well under the 5K
  threshold the plan was sized for, and the residual modularity score
  reflects a repo-wide flatness rather than god files. Speculative
  splitting was deferred; revisit if/when concrete coupling pain emerges.

- **`v2.0.0` git tag** — intentionally not cut in this commit set. Tag at
  release time after a final review and CHANGELOG sweep.
