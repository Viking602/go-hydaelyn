# Venat v0.16.0

Status: **Released** — 2026-08-29

v0.16.0 is an intentional clean cutover from the former platform façade to a
small, direct Agent SDK. It is not source-compatible with v0.15.x. Applications
now compose the `message`, `provider`, `tool`, `skill`, `agent`,
`orchestration`, and optional `durable` packages directly.

## Breaking Agent SDK cutover

- Remove the root `venat.Runner` façade and the platform-owned storage, worker,
  collaboration, policy, session, transport, bundle, sandbox, evaluation, and
  command packages. No compatibility aliases or deprecated shims remain.
- Replace `api.Task` and `api.TaskBudget` with `agent.Request` and
  `agent.Budget`; replace shared hook and stream packages with `agent.Hook`,
  `agent.HookChain`, `agent.Frame`, and `agent.Sink`.
- Move application identity, routing, approvals, quotas, pricing, tracing,
  triggers, deployment records, and domain manifests out of the SDK.
- Make `agent.Spec` plus `agent.Build` the declarative construction path while
  keeping direct `agent.Engine` construction available for explicit
  composition.

See [Migration Notes](../migration.md) for the complete package map, code
examples, and semantic differences.

## Bounded Agent execution

- Provide one bounded `agent.Engine` loop with typed `Request`, `Result`,
  `AgentFailure`, step records, hooks, output guardrails, transient streaming,
  context compaction, and token, tool-call, step, iteration, and wall-clock
  limits.
- Treat `Result.Failure` as terminal Agent data. Infrastructure failure stays
  on the host or durable runtime's Go error boundary.
- Add strict version-1 `Continuation` validation and `Resume` support at safe
  execution boundaries. Unsupported or corrupt continuation state fails
  closed.
- Add `agent.NewAgentTool` for synchronous, in-process delegation to an already
  configured child Engine. It isolates child context, bounds nesting depth,
  forwards safe progress, rolls recursive usage into the parent budget, and
  leaves registry, identity, workflow, process isolation, and independently
  durable child lifecycle to the application.

## Provider, message, tool, and skill contracts

- Normalize provider streams into provider-neutral message content, thinking,
  tool calls, usage, terminal reasons, and partial typed failures.
- Add provider and tool interceptors with immutable inputs, single-effect
  enforcement, and explicit `provider.ErrNotStarted` /
  `tool.ErrNotExecuted` certainty.
- Preserve deterministic operation IDs across retry and resume so provider and
  tool effects can be correlated without application records in the SDK.
- Add typed tool definitions, argument validation, concurrency groups,
  timeouts, bounded update streams, and output normalization.
- Parse, register, discover, and inject Agent Skills-compatible instruction
  resources without turning advisory skill metadata into runtime policy.

## Policy-free orchestration

- Replace the former collaboration and workflow surfaces with the small
  `orchestration.Scheduler`, `Dispatch`, `State`, `Executor`, and `Drive`
  protocol.
- Keep scheduling strategy, identity, routing data, and persisted orchestration
  state in the application. `Drive` performs only bounded, deterministic
  mechanical dispatch.

## Optional durable execution

- Add the twelve-operation `durable.Backend` contract, fenced leases,
  versioned checkpoints, provider/tool attempt settlement, explicit unknown
  effects, and `durable.Runtime` start, resume, and reconciliation flows.
- Ship `durable/contract.RunBackendContractTests`, including process-reopen and
  concurrency coverage, for every external backend implementation.
- Do not ship a production backend or silently retry ambiguous effects.
  Applications investigate unknown effects, reconcile them explicitly, and
  persist orchestration state separately.

## Upgrade

```sh
go get github.com/Viking602/venat@v0.16.0
go mod tidy
```

Then replace root and removed-package imports using the
[Migration Notes](../migration.md). In particular:

- inspect `agent.Result.Failure` separately from infrastructure errors
- treat streaming frames as transient rather than an exactly-once event log
- retry an effect automatically only when `provider.ErrNotStarted` or
  `tool.ErrNotExecuted` proves it did not begin
- run `durable/contract.RunBackendContractTests` before deploying an external
  durable backend

## Verification

- Focused Agent SDK suites:
  `go test ./agent ./message ./provider/... ./tool/... ./skill/...`
- Orchestration suite: `go test ./orchestration`
- Durable runtime and backend contract suites: `go test ./durable/...`
- Executable smokes: `go run ./examples/agent`,
  `go run ./examples/subagent`, `go run ./examples/orchestration`, and
  `go run ./examples/durable`
- Fast gate: `make verify`
- Full CI-parity gate: `make ci-local`
